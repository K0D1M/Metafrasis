# Μετάφρασις

Πλατφόρμα διαχείρισης μεταφράσεων για μικρές ομάδες που τοπικοποιούν βιντεοπαιχνίδια.
Τα κείμενα του παιχνιδιού ζουν σε αρχεία JSON· η ομάδα τα μεταφράζει σε κοινό περιβάλλον,
σχολιάζει ανά κείμενο και παρακολουθεί την πρόοδο ανά κεφάλαιο.

Web εφαρμογή — τρέχει σε browser, άρα δουλεύει σε Windows και macOS χωρίς αλλαγές.

## Τεχνολογίες

| Κομμάτι       | Τι χρησιμοποιεί                                                        |
| ------------- | ---------------------------------------------------------------------- |
| Client        | React 18 + Vite, React Router, εγκαθίσταται ως PWA                     |
| Server        | Express 4 + Prisma 6, σύνδεση με JWT σε httpOnly cookie, argon2        |
| Κοινός κώδικας| Τύποι και σχήματα Zod στο `shared/`                                    |
| Βάση          | Postgres στο Supabase                                                  |
| Αρχεία εικόνων| Supabase Storage, ιδιωτικό bucket `screenshots`                        |
| Φιλοξενία     | Railway: ένα service σερβίρει και το API και το build του client       |

## Απαιτήσεις

- Node.js 22+ (το `engines` στο `package.json` το απαιτεί)
- Ένα project στο Supabase: βάση Postgres και Storage

## Μεταβλητές περιβάλλοντος

Ο server τις διαβάζει από το `server/.env` τοπικά και από τις Variables του service στο
Railway. Τιμές δεν μπαίνουν ποτέ στο repo· το `.gitignore` αγνοεί κάθε `.env`.

| Μεταβλητή             | Υποχρεωτική     | Τι είναι                                                                 |
| --------------------- | --------------- | ------------------------------------------------------------------------ |
| `DATABASE_URL`        | Ναι             | Σύνδεση Postgres μέσω του pooler του Supabase (pgbouncer), για το app    |
| `DIRECT_URL`          | Ναι             | Απευθείας σύνδεση Postgres, για τα migrations (ο pooler δεν τα υποστηρίζει) |
| `JWT_SECRET`          | Ναι             | Κλειδί υπογραφής του cookie συνεδρίας                                    |
| `SUPABASE_URL`        | Ναι             | Το URL του project στο Supabase                                          |
| `SUPABASE_SECRET_KEY` | Ναι             | Secret key (`sb_secret_…` ή το παλιό `service_role`)· μόνο στον server   |
| `CLIENT_ORIGIN`       | Σε production   | Το δημόσιο domain της εφαρμογής, χωρίς `/` στο τέλος. Από αυτό φτιάχνονται οι σύνδεσμοι πρόσκλησης και επαναφοράς κωδικού. Σε dev: `http://localhost:5173` |
| `NODE_ENV`            | Σε production   | `production` ενεργοποιεί τους ελέγχους παραγωγής και κλείνει τα CORS headers του dev |
| `PORT`                | Όχι             | Θύρα του server· προεπιλογή `3001` (το Railway τη δίνει μόνο του)        |

Ο server αρνείται να ξεκινήσει αν λείπει κάποια υποχρεωτική μεταβλητή, αντί να δουλέψει
μισός.

## Ξεκίνημα

```bash
npm install                    # εγκαθιστά, χτίζει το shared/ και τρέχει prisma generate
# φτιάξε το server/.env με τις μεταβλητές του παραπάνω πίνακα
npm run db:migrate             # εφαρμόζει τα migrations στη βάση του DATABASE_URL / DIRECT_URL
npm run db:seed -w server      # προαιρετικά: δοκιμαστικά δεδομένα
npm run dev                    # server στο :3001, client στο :5173
```

Άνοιξε <http://localhost:5173>. Το Vite προωθεί το `/api` στον server, ώστε το cookie
συνεδρίας να μένει στην ίδια origin.

Χρησιμοποίησε ξεχωριστή βάση Supabase για το dev, όχι αυτή της παραγωγής: το seed και το
`prisma migrate dev` γράφουν σε όποια βάση δείχνει το `DATABASE_URL`.

Λογαριασμοί από το seed:

| Ρόλος        | Email                        | Κωδικός       |
| ------------ | ---------------------------- | ------------- |
| Διαχειριστής | `manager@metafrasis.dev`     | `password123` |
| Μεταφραστής  | `translator@metafrasis.dev`  | `password123` |

Ο γενικός διαχειριστής της εφαρμογής (σελίδα Admin) ορίζεται με `isAdmin = true` στον
πίνακα `User`· δεν υπάρχει ακόμα κουμπί στο UI γι' αυτό.

## Παραγωγή (Railway)

Ένα μόνο service. Το `npm run build` χτίζει με τη σειρά `shared`, `server` και `client`,
και ο server σερβίρει το `client/dist` με SPA fallback, άρα API και εφαρμογή ζουν στο ίδιο
URL χωρίς CORS.

```bash
npm run build                  # build command
npm run start -w server        # start command: prisma migrate deploy και μετά node dist/index.js
```

Τα migrations εφαρμόζονται σε κάθε εκκίνηση. Στην πρώτη εκκίνηση ο server δημιουργεί και
το ιδιωτικό bucket `screenshots` στο Supabase Storage, αν δεν υπάρχει. Έλεγχος υγείας:
`GET /api/health`.

## Τι υπάρχει ήδη

- **Λογαριασμοί και ρόλοι**: Διαχειριστής / Μεταφραστής ανά project, με έλεγχο στον server
- **Σύνδεση με email ή όνομα χρήστη**: και τα δύο είναι μοναδικά στη βάση
- **Προσκλήσεις μελών**: σύνδεσμος πρόσκλησης ανά project
- **Επαναφορά κωδικού**: «Ξέχασες τον κωδικό;» στη σελίδα σύνδεσης. Χωρίς SMTP ακόμα, ο
  σύνδεσμος εμφανίζεται στην οθόνη (ίδιο μοτίβο με τις προσκλήσεις), λήγει σε 1 ώρα και
  χρησιμοποιείται μία μόνο φορά
- **Προφίλ**: avatar και προσωπικές ρυθμίσεις, όπως πόσα κείμενα δείχνει το πάνελ
  «Μεταφράστηκε τελευταία»
- **Σελίδα Admin**: όλα τα projects και οι χρήστες, διαχείριση μελών, απενεργοποίηση και
  επαναφορά λογαριασμών. Ένας απενεργοποιημένος λογαριασμός δεν συνδέεται, τα δεδομένα
  του μένουν, και εμφανίζεται παντού ως `deactivated_user_<id>`
- **Δημιουργία project**: όνομα, γλώσσα πηγής, γλώσσες στόχου
- **Ανέβασμα αρχείων**: JSON έως 10 MB, με drag and drop και φακέλους. Η πρόοδος
  του ανεβάσματος εμφανίζεται ζωντανά και επιβιώνει σε ανανέωση της σελίδας
- **Ήδη μεταφρασμένα κείμενα**: όπου το πρωτότυπο είναι ήδη στο αλφάβητο της γλώσσας-στόχου,
  γίνεται αυτόματα και μετάφραση, ώστε να μετρά στην πρόοδο
- **Επεξεργαστής κειμένων**: πρωτότυπο δίπλα σε μετάφραση, με virtualized λίστα για μεγάλα
  αρχεία, σήμανση «Χρειάζεται έλεγχος» και «Δεν χρειάζεται μετάφραση», σχόλια και απαντήσεις
- **Αναφορές με @**: `@όνομα` σε σχόλιο ειδοποιεί το μέλος· ονόματα που δεν είναι μέλη
  και διευθύνσεις email αγνοούνται
- **Ειδοποιήσεις**: καμπανάκι για ανάθεση εργασίας, απάντηση, αναφορά, νέα ή επιλυμένη
  αναφορά QA και ανέβασμα ή Ενημέρωση αρχείου. Κανείς δεν ειδοποιείται για τη δική του ενέργεια
- **Πρόοδος**: μπάρα ανά project και ανά αρχείο. Μετρά μόνο κείμενο στο σωστό αλφάβητο,
  και ένα αρχείο σημασμένο ως ολοκληρωμένο μετρά ολόκληρο
- **PWA**: εγκαθίσταται ως εφαρμογή, με ειδοποίηση όταν υπάρχει νέα έκδοση. Το `/api` δεν
  αποθηκεύεται ποτέ στο cache, ώστε όλη η ομάδα να βλέπει τα ίδια δεδομένα
- **Θέμα**: φωτεινό / σκοτεινό, με προεπιλογή από το σύστημα

## Πώς διαβάζονται τα αρχεία JSON

Το `server/src/services/jsonFlatten.ts` μετατρέπει εμφωλευμένο JSON σε επίπεδη λίστα
κειμένων και το ξαναχτίζει στην ακριβή αρχική δομή για την εξαγωγή.

```json
{ "chapter1": { "intro": { "line1": "Hello" } } }
```

γίνεται ένα κείμενο με κλειδί `chapter1.intro.line1`. Κλειδιά που περιέχουν τελεία ή
backslash γίνονται escape, ώστε η διαδρομή να αποκωδικοποιείται μονοσήμαντα.

Αυτό το round-trip είναι το πιο κρίσιμο σημείο του project: αν χαλάσει, κάθε εξαγωγή
καταστρέφει σιωπηλά τα αρχεία του παιχνιδιού. Γι' αυτό καλύπτεται από τα πρώτα tests
που γράφτηκαν.

## GitHub integration

Καρτέλα Integrations, μόνο για διαχειριστές (οι μεταφραστές βλέπουν την κατάσταση).

1. **Σύνδεση** — αποθετήριο (`owner/repo` ή URL), branch, φάκελος αρχείων πηγής
   (π.χ. `locales/en`) και φάκελος μεταφράσεων με `{lang}` (π.χ. `locales/{lang}`).
   Χρειάζεται ένα fine-grained personal access token μόνο για αυτό το αποθετήριο, με
   **Contents** και **Pull requests: Read and write**. Ελέγχεται πριν αποθηκευτεί και
   φυλάσσεται κρυπτογραφημένο (AES-256-GCM)· δεν επιστρέφει ποτέ στον browser.
2. **Εισαγωγή** — «Έλεγχος αλλαγών» δείχνει ποια `.json` είναι νέα, άλλαξαν ή είναι ίδια.
   Η εισαγωγή περνά από την ίδια διαδρομή με την Ενημέρωση, άρα δεν χάνεται μετάφραση.
   Υποφάκελοι γίνονται φάκελοι του project (`ui/menus/main.json` → φάκελος `ui/menus`).
   Αρχεία που είχαν ανέβει χειροκίνητα με την ίδια διαδρομή αναγνωρίζονται, όχι διπλότυπα.
3. **Αποστολή** — γράφει τα μεταφρασμένα αρχεία με ένα commit στο branch
   `metafrasis/translations-<lang>` και ανοίγει Pull Request προς το branch βάσης. Οι
   επόμενες αποστολές ενημερώνουν το ίδιο ανοιχτό PR· μετά το merge ξεκινά νέο. Στέλνονται
   μόνο αρχεία που ήρθαν από το GitHub.

Προαιρετικές μεταβλητές περιβάλλοντος:

| Μεταβλητή          | Τι κάνει                                                                   |
| ------------------ | -------------------------------------------------------------------------- |
| `GITHUB_TOKEN_KEY` | Κλειδί κρυπτογράφησης των tokens. Χωρίς αυτό παράγεται από το `JWT_SECRET` — αλλαγή του σημαίνει νέο token. |
| `GITHUB_API_URL`   | Για GitHub Enterprise Server, π.χ. `https://github.example.com/api/v3`.     |

## Ενημέρωση αρχείου — τι γίνεται με τις μεταφράσεις

Μια Ενημέρωση **δεν διαγράφει ποτέ μετάφραση**. Η σύγκριση γίνεται ανά διαδρομή κλειδιού:

| Κατάσταση                     | Τι συμβαίνει                                        |
| ----------------------------- | --------------------------------------------------- |
| Κλειδί και στις δύο εκδόσεις  | Η μετάφραση διατηρείται                             |
| Άλλαξε το πρωτότυπο           | Η μετάφραση διατηρείται, με σήμανση «Χρειάζεται έλεγχος» |
| Νέο κλειδί                    | Προστίθεται αμετάφραστο                             |
| Λείπει από τη νέα έκδοση      | Σημαίνεται ως removed, **δεν διαγράφεται**          |

Το τελευταίο είναι σκόπιμο: ένα κλειδί που έφυγε μπορεί να επανέλθει σε επόμενη
αναθεώρηση, και μαζί του η μετάφραση που είχε ήδη γίνει.

## Έλεγχοι

```bash
npm test     # flatten round-trip, διαφορές Ενημέρωσης, πρόοδος, αναφορές με @, HTTP headers
```

Ένα από τα tests αξίζει αναφορά: το `contentDisposition.test.ts`. Οι τιμές των HTTP
headers είναι Latin-1, οπότε ένα ελληνικό όνομα project στο `Content-Disposition`
έριχνε ολόκληρο τον διακομιστή κατά τη λήψη του `.zip`. Το `attachmentHeader()` δίνει
ASCII fallback μαζί με το πραγματικό όνομα σε `filename*` (RFC 5987), και ο διακομιστής
πλέον καταγράφει τις ανεπιτήρητες εξαιρέσεις αντί να τερματίζει.

## Βάση δεδομένων

Postgres στο Supabase μέσω Prisma. Το σχήμα είναι στο `server/prisma/schema.prisma` και τα
migrations στο `server/prisma/migrations/`. Το app συνδέεται μέσω του pooler
(`DATABASE_URL`) και τα migrations απευθείας (`DIRECT_URL`).

| Εντολή                 | Τι κάνει                                              |
| ---------------------- | ----------------------------------------------------- |
| `npm run db:migrate`   | Νέο migration σε dev (`prisma migrate dev`)           |
| `npm run db:studio`    | Prisma Studio για να δεις τα δεδομένα                 |
| `npm run db:seed -w server` | Δοκιμαστικά δεδομένα                             |

Οι εικόνες (στιγμιότυπα) δεν μπαίνουν στη βάση: ζουν στο ιδιωτικό bucket `screenshots` του
Supabase Storage και ο server δίνει προσωρινούς υπογεγραμμένους συνδέσμους, μόνο σε μέλη
του project.
